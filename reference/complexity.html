Complexity

How to read time and space complexity straight off the shape of the code, and how to turn an input bound into a verdict about which approach you are allowed to use.

Algorithms workspace · TypeScript · Last updated after Lesson 5

The reading procedure

Big-O is not a formula you derive. It is a shape you recognise. Four steps, in order, every time:

  1. Find the innermost line that does real work. A comparison, a swap, an assignment, a hash lookup. Ignore everything else.
  2. Count how many times it runs, as a function of n. Not exactly — approximately. You want the shape, not the constant.
  3. Drop constants and lower-order terms. 3n² + 90n + 7 is O(n²). Always.
  4. Add the hidden loops. Every call inside your loop has its own cost. arr.includes(x) inside a loop over arr is two nested loops wearing one line of code.

Shape → complexity

This table is the whole skill. Nine shapes cover almost every interview answer.

ComplexityThe shape in codeWhere you have seen it
O(1) No loop over the input. Arithmetic, one index, one hash lookup. map.get(k), arr[i], arr.push(x)
O(log n) One loop, and the range halves each pass — i *= 2, hi = mid, n = n / 2. Binary search; the depth of merge sort's split
O(n) One loop over the input. Or several loops one after another — sequential loops add, they do not multiply. merge; the hash-map pass of Two Sum
O(n log n) Split the input in half, recurse on both, and do linear work to combine. Or: sort the input, then one pass. Merge sort; arr.sort()
O(n²) Two nested loops, both over the input. Including when the inner one is bounded by the outer — that halves the work and changes nothing asymptotically. Insertion sort; brute-force Two Sum
O(n · m) Two nested loops over two different inputs. Do not collapse this to n² — say both letters. Substring search; grid traversal (rows × cols)
O(n³) Three nested loops over the input. Naive three-sum
O(2ⁿ) Recursion that branches twice and does not shrink the problem by half — a take-it-or-leave-it choice per element. All subsets; naive recursive Fibonacci
O(n!) Recursion that tries every remaining element at every position. All permutations; travelling salesman by brute force
The trap that catches everyone

A triangular nested loop is still O(n²). Insertion sort's inner loop only walks back over the sorted prefix, so it does n(n−1)/2 comparisons, not n². At n = 1000 that is 499,500 rather than 1,000,000 — genuinely half the work, and still O(n²).

Big-O throws away the ½. That is not a flaw in the notation; it is the notation doing its job. A constant factor does not change what happens when n doubles, and what happens when n doubles is the only question Big-O answers.

Simplification rules

Drop constant factors.
O(3n) is O(n). O(n/2) is O(n).
Drop lower-order terms.
O(n² + n) is O(n²). The bigger term wins for large n, and Big-O only describes large n.
Sequential work adds; nested work multiplies.
Loop, then another loop → O(n + n) = O(n). Loop inside a loop → O(n · n) = O(n²). This one distinction resolves most disagreements.
Keep distinct variables distinct.
Two inputs of different sizes give O(n + m) or O(n · m). Collapsing them to n loses real information and interviewers notice.
The base of a log does not matter.
log₂n and log₁₀n differ by a constant factor, which rule one just deleted. Write O(log n).

Space complexity — what actually counts

Space is extra memory, beyond the input you were handed. Two things to add up:

SourceHow to count itExample
Allocations Anything you create whose size grows with n — an output array, a Map, a slice(), a spread copy. Two Sum's hash map: O(n)
Call stack The maximum depth of the recursion, not the total number of calls. Splitting in half gives depth log n; peeling one element gives depth n. Merge sort's stack: O(log n)

So merge sort is O(n) space: the arrays it allocates dominate the O(log n) stack. Insertion sort is O(1): a few index variables, whatever n is. A handful of counters is never O(n), no matter how many of them there are.

Hidden allocation in JavaScript

Copying is invisible in JS syntax. arr.slice(), [...arr], arr.concat(b), and str1 + str2 all allocate. A copy inside a loop turns O(n) time into O(n²) time and O(1) space into O(n) space, and nothing in the code looks like a loop.

Bound → verdict

The constraint line in a problem statement is not decoration. It tells you which complexities are allowed, which usually tells you the intended solution before you have thought of one. The bridge is a single number: a modern machine does a few hundred million simple operations per second.

If n is up toYou can affordWhich usually means
10O(n!)Try every permutation. Backtracking.
20–25O(2ⁿ)Every subset. Take-it-or-leave-it recursion.
500O(n³)Three nested loops are fine.
5,000O(n²)Brute-force pairs is acceptable.
10⁶O(n log n)Sort first, then one pass.
10⁷ and upO(n)One pass. Hash map, two pointers, sliding window.
10¹⁸O(log n)Binary search, or maths. You cannot even read the input.

Thresholds are order-of-magnitude heuristics, not laws, and trusted sources disagree at the edges: Laaksonen puts the O(n²) line at n ≤ 5,000 and the USACO Guide at n ≤ 7,500. That disagreement is the lesson — you are choosing between 10⁶ and 10¹⁰, never between 5,000 and 7,500.

How to say it out loud

"n is at most 1,000, so n² is about a million operations — that runs in well under a second. Brute force is allowed here. I will still use the hash map, because O(n) is easier to write correctly than a careful double loop."
That answer is better than "brute force is too slow," because it is true, and it shows you did the arithmetic rather than reciting a rule.

Vocabulary

Big-O
An upper bound on growth. O(n) means "grows no faster than linearly, ignoring constants." In interviews it is used loosely to mean the actual growth rate; say worst case or average case when it matters.
Amortised
Cost averaged over a sequence of operations. push is O(1) amortised: most pushes are instant, an occasional one resizes the whole array, and the average stays constant.
Adaptive
An algorithm whose cost improves on already-ordered input. Insertion sort is adaptive; merge sort is not. Big-O in the worst case hides this, which is why the best-case column exists on the sorting card.
In place
O(1) extra space — the algorithm rearranges the input rather than building a new structure.
