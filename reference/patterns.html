Patterns

The recurring shapes. Each one has a tell — the thing in the problem that says "use me." Learn the tells, not the problems.

Algorithms workspace · TypeScript · Last updated after Lesson 3

Why patterns at all

Without them, every problem is new and you start from nothing — which is what freezing feels like. A small number of shapes cover most interview questions, so the real skill is classification: deciding which family a problem belongs to, then applying a solution you already know. Aim to name the family before you choose a data structure.

Known

Complement lookup · hash a collection, ask it directly

You need to know whether a specific, computable value exists in a collection. Instead of scanning for it, put the collection in a Map or Set and ask in O(1).

The tell: an inner loop searching for a value you can calculate from the current element — target - x, x / 2, a matching key. If you can compute what you are looking for, you should not be scanning for it.

Trade: O(n²) → O(n) time, at the cost of O(n) space. Trading memory for speed is the most common optimisation in interview problems, and saying that trade out loud is worth marks.

Map or Set? Map when you need where it was (an index). Set when you only need whether it exists.

function twoSum(nums: number[], target: number): number[] {
  const seen = new Map<number, number>();   // value -> index
  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i];
    if (seen.has(complement)) return [seen.get(complement)!, i];
    seen.set(nums[i], i);                    // insert AFTER the check
  }
  return [];
}

The one rule: check before you insert. It is what stops an element pairing with itself, and it means [5] with target 10 correctly returns nothing while [3,3] with target 6 correctly returns [0,1]. No special case required.

Reading the bounds

Before choosing a pattern, convert the input size into a verdict. This is the Bounds line of the problem contract doing its job.

If n is about…You can afford…
n ≤ 20O(2ⁿ) — subsets, backtracking
n ≤ 500O(n³)
n ≤ 5,000O(n²) — nested loops are fine
n ≤ 10⁶O(n log n) — sort, heap, binary search
n > 10⁶O(n) or better — one pass, hash map, two pointers

Worked example. 2 ≤ nums.length ≤ 1000 means n² = 10⁶, so a nested loop is acceptable. Write the simple version without anxiety, then improve it. Change the bound to 10⁵ and n² becomes 10¹⁰ — brute force is dead before you type.

The most common accidental O(n²)

Using arr.includes(x) inside a loop. It looks like a lookup and reads like a lookup, but it is a linear scan. That is precisely the thing the complement-lookup pattern exists to replace.
