Insertion sort

Invariant. At the start of each iteration of the outer loop, the first i elements are sorted among themselves — not necessarily in their final positions.

Shape. Grow a sorted region at the front, one element per pass, sliding each new element leftward until it fits.

function insertionSort(a: number[]): void {
  for (let i = 1; i < a.length; i++) {
    let j = i;
    while (j > 0 && a[j - 1] > a[j]) {
      [a[j - 1], a[j]] = [a[j], a[j - 1]];
      j--;
    }
  }
}

Why it is worth knowing. Adaptive — O(n) on already-sorted input, because every inner loop exits on its first comparison. Stable, because the guard is > rather than >=. Real sorting implementations are hybrids that switch to insertion sort for small or nearly-sorted runs, including Rust's standard library (insertion_sort_shift_left).

Measured. Swap counts from Lesson 2, Exercise 3: [1,2,3,4,5,6] costs 0 swaps; [4,3,2,1] costs 6, which is n(n−1)/2. That gap is O(n) against O(n²), and you produced both numbers yourself.

The two traps

1 · Guard order. Write j > 0 && a[j-1] > a[j], never the reverse. && short-circuits, so a[-1] is never evaluated. Flip them and JavaScript quietly compares against undefined instead of crashing — a silent wrong answer, which is worse than a loud one.

2 · > versus >=. Using >= still sorts correctly, so tests on plain numbers pass. But equal elements now swap past each other and the sort is no longer stable. The bug only appears on records, in production.

Merge sort

Key idea. Merging two already-sorted arrays is the algorithm. The recursion is four lines of bookkeeping on top. Write merge first and the rest follows.

Shape. Split until each piece has one element, then merge back up. Nothing is compared on the way down; all the work is on the way up.

function merge(left: number[], right: number[]): number[] {
  const out: number[] = [];
  let i = 0, j = 0;
  while (i < left.length && j < right.length) {
    if (left[i] <= right[j]) out.push(left[i++]);
    else                     out.push(right[j++]);
  }
  while (i < left.length)  out.push(left[i++]);
  while (j < right.length) out.push(right[j++]);
  return out;
}

function mergeSort(a: number[]): number[] {
  if (a.length <= 1) return a.slice();        // base case — do not omit
  const mid = Math.floor(a.length / 2);
  return merge(mergeSort(a.slice(0, mid)), mergeSort(a.slice(mid)));
}

Why O(n log n). Halving until you reach 1 gives log₂ n levels; each level touches all n elements once while merging. Multiply.

The traps

1 · The base case. Omit if (a.length <= 1) and the recursion never terminates — a one-element array keeps splitting into itself. Stack overflow, not a wrong answer.

2 · <= in the merge. Using < takes from the right half when elements are equal, which breaks stability. Same one-character issue as insertion sort.

3 · Return a.slice(), not a. Returning the original leaks a reference the caller can mutate.

Merge sort's column does not move. It is not adaptive — the shape of the input never changes what it does. Insertion sort's does, dramatically, in both directions.

Use insertion
Small inputs, or data that is already nearly sorted. O(1) space.
Use merge
Large inputs where worst-case behaviour matters, or when you need a guaranteed O(n log n) and can afford O(n) memory.
Real libraries
Use both — O(n log n) for the bulk, falling back to insertion sort on small or nearly-sorted runs.

Proving a sort correct — the three-part invariant

The standard CLRS structure. Worth being able to recite in an interview, because it is the vocabulary for "why is this right?"

Initialization
The invariant is true before the loop starts. Insertion sort: one element is trivially sorted.
Maintenance
If it is true at the start of a pass, it is true at the start of the next. Insertion sort: the pass slides element i into place, so the sorted region grows by one.
Termination
When the loop ends, the invariant gives you the result you wanted. Insertion sort: i reaches n, so all n are sorted among themselves — which is sorted.

Vocabulary

Stable
Equal elements keep their original relative order. Matters when sorting records by one field after another.
Adaptive
Runs faster on input that is already partly sorted. Insertion sort is; merge sort is not.
In place
Uses O(1) extra space beyond the input. Insertion sort is; the usual merge sort is not.
Invariant
A statement that is true at the start of every loop iteration. The tool for reasoning about code you have not run.
